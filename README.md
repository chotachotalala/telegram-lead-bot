# Telegram Lead Bot

Учебный Telegram-бот на Python и aiogram 3 для сбора заявок на услуги.
Подтверждённые заявки сохраняются в локальную базу данных SQLite
`leads.db`.

## Возможности

-   Выбор услуги из списка в `bot_config.json`.
-   Последовательный сбор имени и контактных данных.
-   Проверка телефона, email и Telegram username.
-   Подтверждение заявки перед сохранением.
-   Отмена заявки кнопкой или командой `/cancel`.
-   Сохранение подтверждённых заявок в SQLite (`leads.db`).
-   Отправка уведомления администратору из `bot_config.json`.
-   Проверка конфигурации при запуске.

## Требования

-   Python 3.10 или новее.
-   Токен Telegram-бота, полученный через
    [@BotFather](https://t.me/BotFather).

SQLite входит в стандартную библиотеку Python, поэтому отдельно
устанавливать SQLite или добавлять сторонний пакет для него не
требуется.

## Установка

Откройте терминал в корневой директории проекта.

Создайте виртуальное окружение:

``` bash
python -m venv .venv
```

Активируйте его.

**Windows PowerShell:**

``` powershell
.venv\Scripts\Activate.ps1
```

**Linux и macOS:**

``` bash
source .venv/bin/activate
```

Установите зависимости:

``` bash
python -m pip install -r requirements.txt
```

## Настройка токена

Создайте файл `.env` в корневой директории проекта и добавьте токен:

``` dotenv
BOT_TOKEN=ваш_токен_от_BotFather
```

Замените значение на настоящий токен своего бота. Не публикуйте токен и
не добавляйте файл `.env` в Git.

## Настройка бота

Откройте `bot_config.json`. Пример конфигурации:

``` json
{
  "bot_name": "Telegram Lead Bot",
  "admin_id": 123456789,
  "welcome_message": "Здравствуйте! Выберите услугу:",
  "services": [
    "Telegram-бот",
    "AI-бот",
    "Автоматизация"
  ]
}
```

Замените `123456789` на числовой Telegram ID администратора. Измените
`welcome_message` и список `services` под свой проект. Все обязательные
поля должны присутствовать, а список услуг не должен быть пустым.

## Запуск

Выполните команду из корневой директории проекта:

``` bash
python bot.py
```

После успешного запуска откройте бота в Telegram и отправьте:

``` text
/start
```

## Как работает заявка

1.  Пользователь выбирает услугу.
2.  Вводит имя.
3.  Вводит телефон, email или Telegram username.
4.  Проверяет введённые данные.
5.  Нажимает «Подтвердить» или «Отменить».

Заявка сохраняется только после подтверждения.

## Хранение заявок в SQLite

Заявки хранятся в файле `leads.db` в корневой директории проекта. Файл
базы данных и таблица `leads` создаются автоматически при инициализации
хранилища/первом сохранении заявки.

Таблица `leads` содержит следующие поля:

  Поле                  Описание
  --------------------- ------------------------------------
  `id`                  Уникальный идентификатор записи
  `service`             Выбранная услуга
  `name`                Имя клиента
  `contact`             Контактные данные
  `user_id`             Telegram ID пользователя
  `telegram_username`   Username в Telegram, если указан
  `created_at`          Дата и время создания заявки в UTC

SQLite --- встроенная база данных: отдельный сервер базы данных
запускать не нужно. Бот записывает каждую подтверждённую заявку
отдельной строкой. Если запись не удаётся, ошибка обрабатывается ботом,
и заявка не должна считаться успешно сохранённой.

**Важно:** `leads.db` содержит персональные данные клиентов. Не
публикуйте его в GitHub и не отправляйте посторонним. Убедитесь, что
`.gitignore` содержит как минимум:

``` gitignore
.env
leads.db
leads.db-journal
leads.db-shm
leads.db-wal
```

Если у вас остался `leads.json` от предыдущей версии, он не переносится
в SQLite автоматически этой инструкцией. Сохраните резервную копию
старого файла до возможной отдельной миграции. Не удаляйте его, пока не
убедитесь, что нужные заявки сохранены.

Просмотр сохранённых заявок

Чтобы посмотреть сохранённые заявки из SQLite, откройте терминал в корневой директории проекта и активируйте виртуальное окружение.

Выполните команду:

python -c "import json; from storage import get_leads; print(json.dumps(get_leads(), ensure_ascii=False, indent=2))"

Команда выведет список заявок в формате JSON с полями:

service — выбранная услуга;

name — имя клиента;

contact — контактные данные;

created_at — дата и время создания заявки.

Если заявок нет, команда выведет пустой список [].

Важно: вывод содержит персональные данные клиентов. Не публикуйте его в открытом доступе и не отправляйте посторонним.

Этот способ предназначен для ручного просмотра заявок из терминала. Команда Telegram /leads будет добавлена отдельно.

## Ручная проверка

Перед использованием проверьте следующие сценарии:

-   Выбор доступной услуги и заполнение корректной заявки.
-   Ввод слишком короткого имени.
-   Ввод некорректного телефона, email или username.
-   Подтверждение заявки и появление новой записи в `leads.db`.
-   Отмена через кнопку и команду `/cancel` --- отменённая заявка не
    должна сохраняться.
-   Получение уведомления администратором.
-   Сохранение нескольких заявок.
-   Повторный запуск бота с уже существующим `leads.db`; ранее
    сохранённые записи должны остаться.
-   Обработка отсутствующей или повреждённой конфигурации.
-   Обработка ошибки сохранения заявки.
