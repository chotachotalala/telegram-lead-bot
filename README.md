# Telegram Lead Bot

Учебный Telegram-бот на Python и aiogram 3 для сбора заявок на услуги.
Подтверждённые заявки сохраняются в PostgreSQL.

## Возможности

- Выбор услуги.
- Последовательный сбор имени и контакта.
- Проверка телефона, email, Telegram username или собственного Telegram ID.
- Подтверждение и отмена заявки.
- Сохранение пользователя и заявки в PostgreSQL одной транзакцией.
- Уведомление администратора.
- Просмотр заявок администратором через `/leads` в личном чате.

## Требования

- Python 3.10 или новее.
- Установленный и запущенный PostgreSQL.
- Созданные база данных и таблицы `users` и `leads`.
- Токен Telegram-бота от @BotFather.

## Установка

Откройте терминал в папке проекта.

Создайте виртуальное окружение:

```powershell
python -m venv .venv
```

Активируйте его в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

## Настройка

Создайте файл `.env` в корне проекта:

```dotenv
BOT_TOKEN=your_bot_token
PGHOST=localhost
PGPORT=5432
PGDATABASE=your_database
PGUSER=your_database_user
PGPASSWORD=your_database_password
```

Замените значения своими. Не публикуйте `.env`, токены и пароли.

В `bot_config.json` задайте числовой Telegram ID администратора,
приветствие и список услуг:

```json
{
  "bot_name": "Telegram Lead Bot",
  "admin_id": 123456789,
  "welcome_message": "Здравствуйте! Выберите услугу:",
  "services": [
    "Telegram-бот",
    "AI-бот",
    "Автоматизация"
  ]
}
```

Чтобы получать уведомления, администратор должен сначала открыть
личный чат с ботом и нажать «Старт».

## Подготовка базы данных

Текущая версия ожидает существующие таблицы `users` и `leads`.
Для новой пустой базы структура трёх таблиц приведена в schema.sql. 
Выполните этот файл в pgAdmin, выбрав нужную базу данных. 
Права пользователя базы данных настраиваются отдельно.
Автоматическое создание таблиц и перенос данных из SQLite
не реализованы.

Файл `sql_practice.sql` содержит учебные запросы,
а не команды создания таблиц.

## Проверка подключения

Из корня проекта выполните:

```powershell
python test_postgres.py
```

При успешном подключении скрипт выведет имя базы данных,
пользователя PostgreSQL и версию сервера.

Эта проверка подтверждает подключение, но не проверяет
структуру таблиц и сохранение заявки.

## Запуск

```powershell
python bot.py
```

Откройте бота в Telegram и отправьте `/start`.

Для остановки используйте `Ctrl+C`.

## Путь заявки

1. Пользователь выбирает услугу.
2. Вводит имя и контакт.
3. Бот проверяет введённые данные.
4. Пользователь подтверждает заявку.
5. Бот сохраняет пользователя и заявку в PostgreSQL.
6. Бот отправляет уведомление администратору.

Заявка сохраняется до отправки уведомления.
Ошибка уведомления не отменяет сохранение заявки.

Команда `/cancel` отменяет заполнение.
Команда `/leads` доступна только администратору в личном чате.

## Ручная проверка

Используйте вымышленные заявки.

- Заполните и подтвердите корректную заявку.
- Проверьте получение уведомления администратором.
- Убедитесь, что новая заявка появилась через `/leads`.
- Проверьте отклонение некорректного имени и контакта.
- Отмените заполнение: заявка не должна сохраниться.
- Проверьте отказ в доступе к `/leads` для другого пользователя.
- Перезапустите бота: сохранённые заявки должны остаться доступны.

## Учебные SQL-запросы

В `sql_practice.sql` находятся три примера:

1. Поиск заявок по услуге через `WHERE`.
2. Подсчёт заявок по услугам через `GROUP BY`.
3. Объединение заявок с пользователями через `JOIN`.

дампы базы данных и резервные копии.
